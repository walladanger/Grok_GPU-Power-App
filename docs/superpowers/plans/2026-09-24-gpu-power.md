# GpuPower Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a per-user Windows 11 tray app that shows every display adapter, records live GPU readings, and sets a power limit when that card's driver accepts one.

**Architecture:** A pure Rust library owns limit math, identity, history, export, logging policy, and the sampler's merge rules. A Tauri 2 shell samples once a second, draws the tray icon, and opens borderless WebView2 windows onto one shared snapshot. An elevated mode of the same executable applies limits and display-driver changes. The React page renders that snapshot and does not reimplement clamp math.

**Tech Stack:** Rust 2021, Tauri 2, React 18, Vite, Tailwind CSS, shadcn-style Radix components, Vitest, NVML (`nvml-wrapper`), ADLX loaded from the installed AMD driver, system WebView2.

**Spec:** `docs/superpowers/specs/2026-09-24-gpu-power-design.md`

## Global Constraints

- Sampler tick is once a second. The hot path does not spawn PowerShell or `nvidia-smi`.
- History keeps 15 minutes of full samples. Graph ranges are 1, 5, and 15 minutes. The starting range is 5.
- Main window minimum is 480 by 640. Below width 960, cards stack. At 960 and above, cards sit in equal columns, two per row. The watt figure grows with the card up to 72px.
- A popped-out graph minimum is 480 by 320. A popped-out card or sensor grid minimum is 480 by 640.
- Control hover waits 500ms. A graph sample hover updates immediately. Keyboard focus shows the same help string.
- A sample older than 3 seconds is stale.
- Log file is `%APPDATA%\GpuPower\logs\gpu-power.log`. Roll at 2 MB. Keep 3 files. Detailed debug is off by default. Ordinary one-second samples are not logged.
- Settings file is `%APPDATA%\GpuPower\settings.json`. Start-with-Windows is on by default. The scheduled task name is `GpuPower Reapply Limits`.
- Colors are background `#0a0a0a`, card `#111111`, 1px border at 10% white, primary text `#fafafa`, secondary text `#a1a1aa`. Font is Geist Sans, fallback Segoe UI.
- NVIDIA vendor id is `10DE`. AMD vendor id is `1002`.
- NVIDIA presets are 60, 70, 80, 90, and 100 percent of that card's default watts, rounded to the nearest watt, then clamped to the driver minimum and maximum. On a 100–350 W card with default 350, 80 percent is 280 W.
- AMD presets are the same five percentages mapped across that card's allowed percent range.
- The app does not download a driver, does not delete driver-store packages, and does not reboot Windows.
- Installer is per-user NSIS and uses the system WebView2 already on the machine.
- Fan control, clock offsets, voltage edits, named profiles, timed limits, and per-program limits are not implemented.

## Review Focus

These are the inputs most likely to hurt a person if a task's happy path is all that gets built. The named test in each owning task pins the expected behavior.

- Custom watts applied to every card while an AMD card speaks percent: the AMD card is unchanged and named, and each 3090 receives the watts. Test: `plan_all_custom_watts_skips_percent_card` in Task 1.
- Rollback candidates include the GTX 1050 display package and an AMD chipset package: neither is offered for a 3090. Test: `rollback_rejects_other_device_and_nandisplay` in Task 7.
- Two adapters are both named GeForce RTX 3090 and one disappears: the remaining card keeps its own history and limit, and the missing card stays offline for the session. Test: `reconcile_keeps_uuid_history_when_twin_drops` in Task 2.
- The recording writer fails because the disk is full: recording stops with a reason and the sampler still returns a new snapshot. Test: `disk_full_stops_recording_and_keeps_sample` in Task 9.
- A saved limit is outside the live range, the UUID is gone, or the helper says Windows wants a reboot: clamp the value, skip the missing UUID, tell the user, and do not reboot. Test: `reapply_clamps_skips_and_does_not_reboot` in Task 10.

`preset_value`: for `LimitUnit::Watts`, `((range.default_value as i64) * (percent as i64) + 50) / 100` clamped to `min` and `max`. For `LimitUnit::Percent`, `span = max - min`, then `min + (span * percent as i32 + 50) / 100`, clamped. `plan_limit` accepts preset percents 60, 70, 80, 90, and 100 only.
